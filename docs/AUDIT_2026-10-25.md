## 🔴 긴급 (보안·매출 직결)

**1. 결제 없이 유료 등급이나 관리자(MASTER)를 얻을 수 있습니다.**

- 위치: `server/index.js:3486` `POST /api/payment/verify`
- 원인: 포트원 검증 조건이 `PORTONE_API_KEY && imp_uid`입니다. 요청에서 `imp_uid`만 빼면 검증을 건너뛰고 바로 등급을 줍니다.
- 등급 값은 요청 본문의 `tier`를 그대로 저장합니다. 그래서 `"tier":"MASTER"`를 보내면 DB에 MASTER로 저장됩니다.
- 다시 로그인하면 JWT에 `tier: MASTER`가 들어갑니다. `isAdminToken()`이 `tp.tier === 'MASTER'`를 관리자로 인정하므로 **관리자 권한 전체를 얻습니다.**
- 같은 구조의 문제가 `POST /api/payment/billing/register`(`server/index.js:9680`)에도 있습니다. `imp_uid`를 빼면 무료로 등급을 받고, 이미 다른 사람이 쓰고 있는 VVIP 항구 슬롯도 확인 없이 덮어씁니다.
- 조치:
  - 서버에서 `imp_uid`를 필수로 받습니다.
  - `tier`는 요청 본문에서 받지 않고 서버의 `PLAN_TIERS`로만 정합니다.
  - 테스트 모드 분기는 운영(production)에서 막습니다.
  - VVIP 슬롯은 점유 여부를 확인한 뒤에만 배정합니다.

**2. Google 인앱결제(IAP) 검증 우회**

- 위치: `server/index.js:3250`
- 문제 1: `GOOGLE_PLAY_SERVICE_ACCOUNT`가 설정되어 있지 않거나 Google API가 5xx·네트워크 오류를 내면 "신뢰 모드"로 넘어갑니다. 이때는 아무 토큰이나 통과합니다.
- 문제 2: 같은 구매 토큰이 이미 쓰였는지 확인하는 코드가 **등급을 준 다음에** 실행됩니다. 그래서 토큰 하나로 여러 계정을 업그레이드할 수 있습니다.
- 조치:
  - 신뢰 모드를 없애고, 검증에 실패하면 거절합니다. 5xx 오류면 잠시 뒤 재시도하도록 안내합니다.
  - 중복 검사를 등급 업데이트보다 먼저 합니다.
  - 가능하면 `obfuscatedAccountId`로 구매자와 계정이 일치하는지 대조합니다.
  - Render에 서비스 계정이 실제로 설정되어 있는지 확인이 필요합니다.

**3. 비밀값이 소스에 하드코딩되어 있습니다.**

- 텔레그램 봇 토큰: `tide-guardian-auto-heal.yml:19`, `scripts/notify-telegram.mjs:7`, `server/index.js:1045`
- Render API 키: `tide-guardian-auto-heal.yml:83`, `update-version.cjs:20`
- 조치: 두 키를 재발급하고, 코드의 기본값을 지운 뒤 GitHub Secrets와 Render 환경변수로 옮깁니다.

**4. 텔레그램 웹훅을 위조할 수 있습니다.**

- 위치: `server/index.js:1061`
- 원인: 텔레그램이 보내는 `X-Telegram-Bot-Api-Secret-Token` 헤더를 검증하지 않습니다. 관리자 chat id는 저장소에 공개되어 있습니다.
